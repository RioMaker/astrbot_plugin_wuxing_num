# 数字卦管理页面

重载插件后，从 AstrBot WebUI 的插件详情打开“数字卦管理”。页面通过 AstrBot 官方 Bridge 和已登录的 Dashboard API 工作，不能直接双击 HTML 连接正式数据。支持 `AstrBotPluginView` 及旧的 `AstrBotPluginPage` 名称，页面位于兼容的 `pages/manage/` 目录。

## 内核和测试

“内核与设置”可以保存正式内核、后台 AI 解读模型、指令取根气模型、每日默认额度及开关。保存使用 AstrBot 配置接口，立即影响后续请求；已经开始的正式起卦保持开始时选择的内核。页面保存带修订号，旧页面不会覆盖较新的设置。已有指定群额度规则保留，在标准插件配置中调整。

“起卦实验室”选择本次内核、问题、五个数字及事项五行。测试内核不改变正式配置。

- 不勾选“含 AI 解析”：使用指定五行和本地程序，完全不请求模型。
- 勾选：程序先完成推演，再把本次问题和程序结果交给配置模型解释。AI 不改变保存的程序判定，不访问聊天历史、人格或工具。
- 后台模型未选择时，使用 `command_provider_id`；两者都为空则保留程序结果并提示配置模型。
- 模型错误、超时、空响应保留程序结果，历史标记解读失败，不伪装为成功。
- 结果包含实际生成的 PNG 预览与完整文字；单图容量不足或渲染失败仍能查看文字。
- 后台测试不会向群发送消息，不修改每日群成员额度，不更新经典三次死卦状态；它会实际请求所选模型并保存独立测试记录。

正式指令和 Agent 仍沿用之前的“AI 只取根气、程序解卦”行为。后台 AI 解析是新增的可选测试功能，不能把正式卦例的 AI 取根气误当作已有 AI 解读。

## 排行和历史

调用排行按已保存的正式起卦次数降序展示群与个人，包含成、败、死卦、待定。非法请求、未起卦的 AI 失败、后台测试不进入正式排行。个人按平台实例与账号合并各群调用，群按平台实例及群号统计，避免同号跨平台混淆。同一消息的相同数字、问题、根气和内核去重。每页 30 名，可以翻页，不需要输入账号查询。

历史页保存问卦人账号和昵称、群、平台、问题、北京时间、原始数字、内核与版本、当时的程序推演及可选 AI 解读；可按正式或测试筛选并分页。打开详情或预览历史图不会增加调用次数，也不再次请求 AI。

历史从本版本启用后开始采集；旧版只有每日额度与死卦记录，不能还原旧卦例或历史总排行。

## 精简存储与导出

卦例统一存于 `data/plugin_data/wuxing_num/cases.json`，UTF-8 JSON，紧凑序列化，原子替换写入。只存文字与结果快照，不保存 PNG、聊天历史、密钥或重复的五位关系表。不自动删除历史，全部卦例均可导出。文件损坏时停止写入并报错，不用空文件覆盖损坏数据。

“导出所有卦例”下载 ZIP，包含：

- `cases.json`：全部存储记录，包含正式卦例与后台测试，不受筛选和分页影响。
- `说明.md`：完整字段、枚举、计数口径、时间格式、恢复方法及边界说明。

恢复前先停止插件并备份原文件，再替换 JSON。恢复卦例不恢复每日额度和三次死卦状态。导出文件缓存在数据目录的 `exports/`；再次导出时清理超过 48 小时的旧 ZIP 缓存，不删除卦例 JSON。也可在停止插件后清理导出缓存，无需保留它们才能读取卦例库。

## 本地验证

`python -B tools/preview_management.py` 在回环地址启动隔离的页面验收环境，使用临时数据、25 条模拟正式记录及明确标注的模拟 AI，不连接 QQ、真实部署或在线模型。浏览器访问终端输出地址。结束后关闭进程即可；不应将这个测试服务器用于部署。

正式 API 每个入口均检查 Dashboard 登录身份；测试服务器只是开发工具，不含真实数据。
